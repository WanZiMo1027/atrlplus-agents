# 增量样本与迭代流程

## 什么时候重新分析

- 新增一批 QQ 群导出记录。
- bot 模型、system prompt、触发逻辑或记忆系统有明显变更。
- 线上出现可重复的“AI 味”、乱插话或攻击过强问题。
- 当前低置信度项目积累了新的真实样本。

## 运行分析脚本

在 Skill 目录外创建暂存输出，避免候选结果自动成为正式规则：

```powershell
python .\scripts\analyze_chat_export.py `
  "..\..\group_Jeremie吉他_二次元吹水群_450055647_20260914_224934568.xlsx" `
  --target-qq 3690145414 `
  --target-alias 新世界若叶睦,若叶睦,睦子,小睦 `
  --from-date 2026-07-27 `
  --exclude-qq 3784423819,3763604733 `
  --out .\analysis-staging
```

脚本生成：

- `metrics.json`：数据源、版本分段、长度、标点、粗口及回复倾向指标。
- `candidate_examples.jsonl`：带局部上下文的匿名化候选案例。
- `analysis.md`：适合人工检查的摘要。

输出中不包含 QQ 号或原始昵称。目标、其他 bot 和群友使用稳定代号。脚本只读工作簿，不改写 `SKILL.md` 或 references。

## 审查候选

1. 先确认账号映射、日期范围和导出结构没有变化。
2. 排除媒体依赖、报错、日志、提示词、代码粘贴和集体复读。
3. 按独立日期或会话统计支持度，不按原句出现次数直接投票。
4. 检查行为是否跨话题仍成立，还是只属于一次特殊玩梗。
5. 将可靠行为提升到 `SKILL.md`；数据细节和限制只更新 `evidence.md`。
6. 把能解释规则的少量匿名案例更新到 `examples.md`，不堆积聊天原文。

### 线上失败的专项审计

遇到一句明显不自然的线上回复时，不要立即把原句加入黑名单：

1. 在全部记录和目标账号中分别统计原句、核心短语和近义功能句。
2. 查看出现位置的日期、模型阶段和前后 2–6 条上下文。
3. 判断问题属于词汇偶然、确认后复述、策略播报、客服腔、错误插话还是强度误判。
4. 优先修改产生它的通用决策或自检规则，再把原句作为回归反例。
5. 若短语为零次，明确记录“无样本支持”，不要反向发明成新口癖。

例如“我收着点”在当前 62,230 条记录中为零次。需要修复的不是一个关键词，而是“把内部语气调节说给群友”的生成错误。

## 规则变更标准

- 至少 3 个独立日期/会话且与总体指标一致，才能成为高置信度默认行为。
- 两个独立语境可形成中置信度的条件规则。
- 单次样本只可记录为低置信度观察，不能使用“必须”“总是”。
- 若新旧样本冲突，先检查模型版本和日期；对运行时风格优先采用最近且跨会话稳定的阶段。
- 修复具体失败，避免为每个失败继续叠加新口号、新关键词或固定问答。

## 回归场景

每次修改至少检查：

- 无人叫大肥鱼、无新增价值时输出 `{"shouldReply":false,"reply":""}`。
- 被 @ 但属于重复刷屏时仍可沉默。
- 一句话多个信息点时只接一个点。
- 被夸时措辞可变化，不复读固定台词。
- 熟人轻度互损不升级为现实伤害或家人攻击。
- 陌生人、真实痛苦和正经求助不进入毒舌模式。
- 技术问题先回答，角色设定不挤占信息。
- 不确定的长期记忆不会被说成事实。
- 边界请求只产生必要的最短确认或短道歉，不出现“我会调整/控制/收敛”的策略播报。
- 确认后不再复述对方刚提出的要求。
- 转为认真、安慰或沉默时，直接执行，不说“切换模式/保持沉默”。
